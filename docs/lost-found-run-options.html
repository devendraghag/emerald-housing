Lost & Found run options

Run the member service with Kafka locally from IntelliJ IDEA, or deploy the backend with the project’s Kubernetes manifests. Both paths use the same Lost & Found API, database migration, event topic, and in-app notification consumer.

Local development

Run from IntelliJ IDEA

Start Kafka in Docker, then run MemberServiceApplication from the member-service project in IntelliJ.

1. Start Kafka

From the repository root:

docker compose -f docker-compose.kafka.yml up -d

The broker listens on localhost:9092. The app creates the one-partition lost-found.events topic on startup.

2. Check local dependencies

  • PostgreSQL must be reachable at localhost:5432 with database member_db.
  • Redis must be reachable at localhost:6379.
  • Use the project’s configured member database credentials or set MEMBER_DB_URL, MEMBER_DB_USERNAME, and MEMBER_DB_PASSWORD in the IntelliJ run configuration.

3. Run the service

  1. Open services/member-service as a Maven project in IntelliJ and wait for Maven import.
  2. Open MemberServiceApplication.java, edit the run configuration, and set the working directory to services/member-service.
  3. Run the main method. Set KAFKA_BOOTSTRAP_SERVERS=localhost:9092 in the run configuration.

4. Verify startup

Flyway applies V14__lost_found.sql at startup. Check the console for a successful application start, then call the API through the authenticated gateway at http://localhost:8080/api/v1/lost-found.

Photos: files are stored under services/member-service/var/lost-found when launched with the member-service working directory. The API serves them inline; it does not return an attachment download.

Deploy with Kubernetes

The repository Kustomize base includes the member service and gateway. Kafka runs as a Docker container on the host, and the member service receives KAFKA_BOOTSTRAP_SERVERS=host.docker.internal:9092 from the application ConfigMap. The broker advertises that same host-reachable address so clients can connect after metadata discovery.

1. Start host Kafka

docker compose -f docker-compose.kafka.yml up -d

2. Build the updated image

From services/member-service:

docker build -t emerald/member-service:lost-found .

Update kubernetes/member/deployment.yaml to use that tag, or tag the image with the deployment’s configured tag before applying manifests.

3. Apply the manifests

From repository root, with the intended Kubernetes context selected:

kubectl apply -k kubernetes
kubectl rollout status deployment/member-service -n emerald-housing
kubectl get pods,services -n emerald-housing

4. Check Kafka reachability

The Kubernetes ConfigMap already sets the bootstrap address to host.docker.internal:9092. Confirm that the selected cluster can resolve and reach that host address on TCP port 9092. The broker must advertise a listener reachable from the pods.

Photo persistence: the Kubernetes configuration currently points uploads to /tmp/lost-found. That directory is ephemeral and local to a pod. For multi-replica or production use, replace it with shared persistent storage (or object storage) before relying on uploaded photos across restarts or replicas.
Deployment verification: compiling the member service does not apply the database migration or prove Kubernetes-to-host Kafka connectivity. Verify both against the target cluster before treating the rollout as ready.
What this backend slice supports

Request and event flow

Resident report→PostgreSQL→Admin review→Kafka outbox→In-app notification
  • Residents create Lost or Found reports, optionally attach an image, view published notices, and submit item claims.
  • Administrators review reports, publish or reject them, inspect claims, accept or reject claims, and close reports.
  • Reporter and claimant identifiers and claimant details are returned only by admin endpoints.
  • Events for publication, claims, and resolution are written to a PostgreSQL outbox and dispatched to lost-found.events.
  • The Kafka consumer persists recipient-specific in-app notifications that can be retrieved from GET /api/v1/lost-found/notifications.
