Standalone deployment walkthrough

Deploy the current AI service to Docker Desktop Kubernetes

This independent page follows Option B in indexLatest.html. It guides deployment of the existing Spring AI service alongside the Gateway, Member, Society, and Redis workloads, then exposes the Gateway locally through a port-forward.

Browser / client→localhost:8080→Gateway→AI Service→OpenAI

The AI Deployment has one replica because its FAQ vector index and conversation memory are process-local.

Runtime configuration to know: PostgreSQL host host.docker.internal; Society and Member databases society_db/member_db; session Redis redis:6379; cache Redis redis-cache:6379; Gateway routes AI requests to http://ai-service:8080; AI calls Gateway session validation and Society Service in-cluster. Gateway uses SESSION_COOKIE_SECURE=false for this localhost HTTP walkthrough. The Member config also points Kafka to host.docker.internal:9092; this walkthrough does not deploy Kafka, so Kafka-backed notice flows require a broker already listening there.

Before you start

  • Start Docker Desktop, enable Kubernetes, and wait for its node to become Ready.
  • Keep the existing PostgreSQL databases and credentials available. This walkthrough does not create, reset, or delete databases.
  • Have the existing PostgreSQL password and an OpenAI API key ready. Enter secrets only at hidden prompts.
  • Open PowerShell in D:\Devendra Ghag Interview Preparation\02_Spring\emerald-housing.
Always start fresh. Step 0 hard-deletes only the emerald-housing Kubernetes namespace; step 1 recreates it. This removes its workloads, Services, ConfigMaps, Secrets, policies, and in-cluster Redis data. It preserves the Docker Desktop cluster, local Docker images, and external PostgreSQL databases and rows. Stop old port-forwards and local Java apps first. Do not delete PostgreSQL databases or the Kubernetes cluster.

Walkthrough

0

Hard fresh start: remove the old project namespace

Close any old port-forward terminal with Ctrl+C and stop local Java applications for this project. Start Docker Desktop and PostgreSQL, enable Kubernetes, and wait until it is ready. Select and verify the Docker Desktop context before deleting anything.

Set-Location 'D:\Devendra Ghag Interview Preparation\02_Spring\emerald-housing'
docker info
kubectl version --client
kubectl config use-context docker-desktop
kubectl config current-context
kubectl --context docker-desktop get nodes

Proceed only when current context is docker-desktop and its node is Ready. This command deletes the project namespace only; it does not delete PostgreSQL databases or the cluster.

kubectl --context docker-desktop delete namespace emerald-housing --ignore-not-found=true --wait=true --timeout=300s
kubectl --context docker-desktop get namespace emerald-housing

After deletion, the last command should report NotFound. Stop if deletion times out or the namespace remains Terminating; do not remove finalizers blindly.

1

Ensure the namespace exists

Applying this manifest is safe when the namespace already exists.

kubectl --context docker-desktop apply -f .\kubernetes\namespace.yaml
2

Verify PostgreSQL and configure database credentials

Databases must already exist: society_db and member_db, using PostgreSQL user emerald in this local setup. The applications run Flyway migrations at startup; do not manually drop or reset the external databases. PostgreSQL must accept connections from Docker Desktop on its configured port. The ConfigMap uses host.docker.internal; check listen_addresses, pg_hba.conf, and the host firewall if needed. Optionally verify each database with psql -h localhost -U emerald -d society_db -W and psql -h localhost -U emerald -d member_db -W, entering the existing password at each prompt, then exit psql with \q.

Create the database Secret with the existing password. This changes only Kubernetes connection credentials, not the PostgreSQL password.

$societyUser = 'emerald'
$memberUser = 'emerald'
$databasePassword = [System.Net.NetworkCredential]::new('', (Read-Host 'Existing PostgreSQL password for emerald (both databases)' -AsSecureString)).Password
$societyPassword = $databasePassword
$memberPassword = $databasePassword
kubectl --context docker-desktop create secret generic emerald-db-credentials -n emerald-housing --from-literal="society-username=$societyUser" --from-literal="society-password=$societyPassword" --from-literal="member-username=$memberUser" --from-literal="member-password=$memberPassword" --dry-run=client -o yaml | kubectl --context docker-desktop apply -f -
Remove-Variable databasePassword,societyPassword,memberPassword
kubectl --context docker-desktop get secret emerald-db-credentials -n emerald-housing

Keep credentials out of this page, YAML, Git, and saved commands. Adjust the usernames if your existing DB configuration differs from the documented local setup.

2a

Generate fresh application security credentials

Because step 0 deleted namespace Secrets, generate a new application admin account and matching internal tokens. Save the printed admin login privately for Postman. Existing DB rows and old admin accounts remain in PostgreSQL.

function New-Secret { $bytes = New-Object byte[] 32; $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create(); try { $rng.GetBytes($bytes); [Convert]::ToBase64String($bytes) } finally { $rng.Dispose() } }
$adminUser = 'admin-' + [Guid]::NewGuid().ToString('N')
$adminPassword = [Guid]::NewGuid().ToString('N')
$redisPassword = New-Secret; $cachePassword = New-Secret; $gatewayToken = New-Secret; $sessionToken = New-Secret; $memberToken = New-Secret
kubectl --context docker-desktop create secret generic emerald-security-credentials -n emerald-housing --from-literal="admin-username=$adminUser" --from-literal="admin-password=$adminPassword" --from-literal="redis-password=$redisPassword" --from-literal="redis-cache-password=$cachePassword" --from-literal="gateway-authentication-token=$gatewayToken" --from-literal="session-validation-token=$sessionToken" --from-literal="member-to-society-token=$memberToken" --dry-run=client -o yaml | kubectl --context docker-desktop apply -f -
Write-Host "Postman adminUsername: $adminUser"
Write-Host "Postman adminPassword: $adminPassword"
Remove-Variable adminPassword,redisPassword,cachePassword,gatewayToken,sessionToken,memberToken
3

Build Society, Member, and Gateway images

Use a unique tag and keep this PowerShell terminal open for later steps.

$imageTag = 'option-b-' + (Get-Date -Format 'yyyyMMddHHmmss')
docker --context desktop-linux build -t "emerald/society-service:$imageTag" .\services\society-service
docker --context desktop-linux build -t "emerald/member-service:$imageTag" .\services\member-service
docker --context desktop-linux build -t "emerald/api-gateway:$imageTag" .\infrastructure\api-gateway
4

Apply config and start Redis

PostgreSQL must be reachable from Docker Desktop Kubernetes. The default ConfigMap uses host.docker.internal.

kubectl --context docker-desktop apply -f .\kubernetes\config\application-config.yaml
kubectl --context docker-desktop apply -f .\kubernetes\redis\
kubectl --context docker-desktop apply -f .\kubernetes\redis-cache\
kubectl --context docker-desktop rollout status deployment/redis -n emerald-housing --timeout=180s
kubectl --context docker-desktop rollout status deployment/redis-cache -n emerald-housing --timeout=180s
5

Deploy Society and Member

kubectl --context docker-desktop apply -f .\kubernetes\society\
kubectl --context docker-desktop apply -f .\kubernetes\member\
kubectl --context docker-desktop set image deployment/society-service "society-service=emerald/society-service:$imageTag" -n emerald-housing
kubectl --context docker-desktop set image deployment/member-service "member-service=emerald/member-service:$imageTag" -n emerald-housing
kubectl --context docker-desktop rollout status deployment/society-service -n emerald-housing --timeout=300s
kubectl --context docker-desktop rollout status deployment/member-service -n emerald-housing --timeout=300s
6

Deploy Gateway for localhost HTTP

kubectl --context docker-desktop apply -f .\kubernetes\gateway\config.yaml
kubectl --context docker-desktop apply -f .\kubernetes\gateway\deployment.yaml
kubectl --context docker-desktop apply -f .\kubernetes\gateway\service.yaml
kubectl --context docker-desktop set image deployment/api-gateway "api-gateway=emerald/api-gateway:$imageTag" -n emerald-housing
kubectl --context docker-desktop set env deployment/api-gateway SESSION_COOKIE_SECURE=false -n emerald-housing
kubectl --context docker-desktop rollout restart deployment/api-gateway -n emerald-housing
kubectl --context docker-desktop rollout status deployment/api-gateway -n emerald-housing --timeout=300s
kubectl --context docker-desktop get pods -n emerald-housing

Wait for the base Pods to be ready before deploying AI.

7

Store the OpenAI key in a Kubernetes Secret

The key is read securely and piped directly to Kubernetes. It is not saved in this HTML page or repository.

$openAiSecureKey = Read-Host 'OpenAI API key' -AsSecureString
$openAiPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($openAiSecureKey)
try {
  $openAiKey = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($openAiPtr)
  kubectl --context docker-desktop create secret generic emerald-ai-credentials -n emerald-housing --from-literal="openai-api-key=$openAiKey" --dry-run=client -o yaml | kubectl --context docker-desktop apply -f -
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($openAiPtr)
  Remove-Variable openAiKey -ErrorAction SilentlyContinue
  $openAiSecureKey.Dispose()
}

The Secret name and key must match the AI Deployment: emerald-ai-credentials / openai-api-key.

8

Build and roll out the AI service

Use a fresh image tag, apply the AI Deployment and ClusterIP Service, and wait for the rollout.

$aiImageTag = 'option-b-ai-' + (Get-Date -Format 'yyyyMMddHHmmss')
docker --context desktop-linux build -t "emerald/ai-service:$aiImageTag" .\services\ai-service
kubectl --context docker-desktop apply -f .\kubernetes\ai\
kubectl --context docker-desktop set image deployment/ai-service "ai-service=emerald/ai-service:$aiImageTag" -n emerald-housing
kubectl --context docker-desktop rollout status deployment/ai-service -n emerald-housing --timeout=300s
kubectl --context docker-desktop get pods -l app=ai-service -n emerald-housing
kubectl --context docker-desktop logs deployment/ai-service -n emerald-housing --tail=100

OpenAI is the default provider for chat and embeddings. AI validates sessions through Gateway and calls Society for its restricted maintenance tool. The AI Service stays internal to the cluster; public traffic enters through Gateway.

9

Forward Gateway to localhost

Open a second PowerShell terminal and leave this running:

kubectl --context docker-desktop port-forward service/api-gateway 8080:8080 -n emerald-housing

Use http://localhost:8080. If port 8080 is occupied, stop the conflicting local Gateway or old port-forward, then retry.

10

Check readiness and the assistant route

Invoke-RestMethod http://localhost:8080/actuator/health/readiness
kubectl --context docker-desktop get deployments,pods,services -n emerald-housing

Expect Gateway readiness to report UP; confirm Society, Member, Gateway, AI Service, Redis, and Redis Cache are ready. Gateway readiness does not prove OpenAI connectivity or assistant behavior. After signing in, send POST /api/v1/assistant/questions with the session cookie, XSRF cookie, and X-XSRF-TOKEN header. A successful response includes conversationId, answer, and sources.

If a step fails

Stop at the first failing rollout. Inspect Pods, events, and logs. Do not delete the namespace or database to troubleshoot.

kubectl --context docker-desktop get pods -n emerald-housing
kubectl --context docker-desktop get events -n emerald-housing --sort-by=.lastTimestamp
kubectl --context docker-desktop logs deployment/ai-service -n emerald-housing --tail=100
kubectl --context docker-desktop describe deployment/ai-service -n emerald-housing

After changing the OpenAI key, repeat the secure Secret prompt and restart AI so its environment refreshes:

kubectl --context docker-desktop rollout restart deployment/ai-service -n emerald-housing
kubectl --context docker-desktop rollout status deployment/ai-service -n emerald-housing --timeout=300s

11. Hard teardown after verification

First stop the port-forward with Ctrl+C in its terminal. Then remove the complete project namespace. This deletes all project Kubernetes workloads and in-namespace Secrets/ConfigMaps; it does not stop/delete the Docker Desktop cluster, delete local images, or remove external PostgreSQL databases or their rows.

kubectl --context docker-desktop delete namespace emerald-housing --wait=true --timeout=300s
kubectl --context docker-desktop get namespace emerald-housing

Wait for deletion. The final check should return NotFound. If deletion times out or remains Terminating, inspect and stop; do not strip finalizers blindly. PostgreSQL continues running with its data intact.

End of Option B

Ctrl+C stops the port-forward only; workloads continue until the namespace teardown above completes. Start from step 0 for the next walkthrough. No database or cluster deletion is required.
