Emerald Housing manual functional test cases

Role-based end-to-end checks for the Vue frontend and Spring Boot backend. Start each case from the sign-in page. Sign in with the test account and role named in the case, then use the workspace navigation or the named page link to reach the feature. Follow the numbered journey and verify the visible result plus saved data/access behavior. Security and attack-protection checks are marked separately and should run only in an authorized non-production environment. Mark each case and add actual observations.

Role setup: access is permission and scope based. “Admin”, “Owner”, “Tenant”, and “Family” below describe expected user setups, not assumptions that every deployment has those exact built-in accounts. Confirm the test account’s effective permissions and flat assignments first. A flat owner account and a staff/manager account with OWN_FLATS scope are distinct setups; test both when both are used. A family record does not create a login by itself: the person must be linked and an account with suitable grants configured. A denied action should be tested by navigating directly as well as checking whether the UI hides it.

Results are saved in this browser on this device. Clear them with “Reset results”. Do not put passwords, session cookies, or personal resident data in notes. Checks that create, change, or deactivate records should use designated test data and be cleaned up after the run.
